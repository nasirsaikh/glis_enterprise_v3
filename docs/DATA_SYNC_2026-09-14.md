# Updated content synchronization - 2026-09-14

This update merges the database content from the supplied updated `glis_enterprise_v3` ZIP into the newer repository schema instead of replacing newer application code.

## What is imported

`apps/core/migrations/0010_import_updated_zip_content.py` loads the supplied SiteSettings, services, features, statistics, general/medical process steps, testimonials, FAQs, management team, insurer partners, provider types, locations, specialties, network providers and their M2M relations, TPA services, medical contacts, and download-center metadata.

The old `HeroSection` values are mapped to the hero fields now stored on `SiteSettings`. The old `MedicalProcessStep` rows are mapped to the unified `ProcessStep` model as `CLAIM` and `PREAUTH` processes. Legacy `HomeSection` rows are archived under `apps/core/data/content_archive/` because the latest schema intentionally removed that model.

## Media handling

The repository currently does not version Django `MEDIA_ROOT`. For deployment safety, the data migration therefore preserves existing `FileField` / `ImageField` values instead of writing paths to files that may not exist on the target environment. New records whose required file is unavailable are skipped rather than creating broken download records.

The supplied ZIP media was inspected separately and retained in the migration handoff package / merged SQLite snapshot. Media should be copied to the configured Django media storage (or object storage) independently of application source code.

## Applying the update

Run:

```bash
python manage.py migrate
```

Migration `core.0010_import_updated_zip_content` updates the content rows to match the supplied snapshot while preserving repository-newer schema changes and existing media-storage references.
