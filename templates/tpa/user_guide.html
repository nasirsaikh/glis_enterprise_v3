{% translate "2. Initial setup" %}

  1. {% translate "Create the Sponsor/Corporate organization and Insurance Company in TPA Organizations." %}
  2. {% translate "Create the Policy with its start/expiry dates, status, backdating limit, STP setting and premium setting." %}
  3. {% translate "Create one or more Benefit Plans under the policy and configure annual premium, sum insured and premium method." %}
  4. {% translate "Create Policy Access records for users who should see or act on that policy." %}
  5. {% translate "Assign the relevant TPA permissions to users or groups for dashboard, creation, approval, processing and configuration." %}

{% translate "3. Using the TPA dashboard" %}

{% translate "Open TPA Member Management from the portal sidebar. The dashboard summarizes Active Sponsors, Active Policies, Active Members, Open Transactions, Needs Information, Pending Approval and STP Rate for records you are authorized to see." %}

{% translate "Recent Transactions provides the TPA reference, linked GLIS ticket, sponsor, policy, transaction type, source, validation score, STP eligibility and current status." %}

{% translate "4. Create and submit an endorsement" %}

  1. {% translate "Select New Endorsement. The button appears only when your account can create TPA transactions." %}
  2. {% translate "Choose a policy from the policies available to your account." %}
  3. {% translate "Choose the transaction type: New Policy Enrollment, Member Addition, Member Termination, Member Deletion/Void or Policy Cancellation." %}
  4. {% translate "Enter the requested effective date and remarks, then save the draft." %}
  5. {% translate "Add members manually or upload a CSV/XLSX spreadsheet. Use the built-in Valid Sample CSV/XLSX buttons on the transaction screen as the reference format." %}
  6. {% translate "For a spouse, child or other dependent, select the Parent Principal. Add the principal row first if the principal is part of the same new enrollment. Spreadsheet dependents can use principal_employee_id to point to a principal row in the same file, or principal_member_id for an existing TPA principal." %}
  7. {% translate "Review row-level validation, premium impact and the member-quality/error charts." %}
  8. {% translate "Submit the draft. GLIS creates the operational ticket and runs deterministic validation immediately." %}
  9. {% translate "If validation fails, correct/remove rows and run validation again. If it passes, the transaction moves to STP auto-approval or approval according to policy and ticket rules." %}
  10. {% translate "After approval, a user with TPA processing authority selects Process Transaction to create/update the member enrollment and complete the transaction." %}
  11. {% translate "Use the linked GLIS ticket for SLA, approvals, assignment, notifications and operational collaboration." %}

{% translate "5. Transaction statuses" %}

{% translate "Draft" %} — {% translate "Saved but not yet submitted." %}
{% translate "Pending Validation" %} — {% translate "Submitted for deterministic validation." %}
{% translate "Needs Information" %} — {% translate "More or corrected information is required." %}
{% translate "Pending Approval" %} — {% translate "Waiting for configured approval." %}
{% translate "Auto Approved" %} — {% translate "Eligible for rules-based straight-through approval." %}

{% translate "6. Premium calculation" %}

{% translate "Premium calculation is deterministic. Benefit Plan configuration supports Full, Lump Sum, Partial and Prorata calculation methods. Monetary values are calculated with Decimal arithmetic and rounded to three decimal places for OMR-style precision." %}

{% translate "The transaction and member action retain calculation snapshots so the basis used for the amount can be audited later." %}

{% translate "7. AI and document intake" %}

{% translate "AI extraction is operational through admin-configured Mock, Ollama, OpenAI-compatible/OpenAI and Anthropic providers. Providers can be marked for text/vision capabilities and sensitive-data use. Email body extraction and vision-capable image attachments produce canonical member JSON; CSV/XLSX attachments use deterministic structured import." %}

{% translate "AI only extracts and maps source data. Eligibility, validation, premium, STP, approval and final processing remain deterministic application rules." %}
{% translate "PDF attachments are retained and flagged for review in the current implementation; configure/test a dedicated PDF/OCR path before relying on automatic PDF extraction." %}

{% translate "8. Email intake" %}

{% translate "Use TPA Operations → Inbound Emails → Add Inbound Email. Enter the email body, optionally give policy/type/effective-date hints, attach CSV/XLSX or images, and keep Process with AI enabled. The system stores the email and attachments, audits the AI interaction, creates the TPA transaction and GLIS ticket, then runs deterministic validation/STP." %}

{% translate "CSV/XLSX email attachments are imported directly; image attachments use a configured vision provider. Duplicate provider message IDs are prevented and files requiring review remain visible on the inbound email detail page." %}

{% translate "9. Administrator checklist" %}

  • {% translate "Confirm organizations, policies and benefit plans are active and dated correctly." %}
  • {% translate "Assign TPA permissions through Django users/groups." %}
  • {% translate "Create Policy Access for the correct user and organization." %}
  • {% translate "Configure policy backdating, STP and premium rules." %}
  • {% translate "Configure AI Provider Config with capability email_extraction; enable allow_sensitive_data for member/email content. For image extraction also enable supports_vision and document_extraction." %}
  • {% translate "For Ollama/OpenAI/Anthropic credentials, Secret reference is the environment-variable name, not the secret value itself." %}
  • {% translate "Use the linked GLIS ticket to monitor SLA, approvals, assignment, notifications and audit events." %}
