{% translate "2. Initial Policy Enrollment" %}

{% translate "Use TPA Operations → Initial Policy Enrollment for a brand-new policy. New Policy Enrollment is intentionally not available in the Endorsement menu." %}

  1. {% translate "Select an Individual or Corporate Sponsor, Insurance Company and optional TPA route." %}
  2. {% translate "Enter policy number/name, start/end dates, currency, STP and backdating settings." %}
  3. {% translate "Create the first benefit plan; additional plans can be added inside the setup case." %}
  4. {% translate "Load the opening census using manual entry or the same Excel/CSV/PDF/image OCR intake used by endorsements." %}
  5. {% translate "Submit, validate, approve/STP, process at TPA level and complete." %}

{% translate "The policy starts as Draft. Successful TPA completion activates it and records the initial-enrollment completion time/user. Only then does it become available to New Endorsement, except legacy policies that already have active enrollments." %}

{% translate "5. Validation, Pricing & Approval" %}

{% translate "Validation checks policy period/backdating, mandatory fields, plan validity, duplicates, active-member lookup and dependent/principal relationships. Premium/refund calculations use Decimal arithmetic and the policy-plan configuration." %}

{% translate "Clean STP-eligible cases auto-approve and dispatch to the TPA queue. Otherwise the linked GLIS approval workflow or a permitted approver completes approval. Approval now means dispatch to TPA; it does not immediately mutate member records." %}

{% translate "6. TPA Processing & Embedded Query Chat" %}

{% translate "A TPA processor starts the dispatched case, records card/member number, TPA effective date and TPA premium/refund amount per row, then completes the transaction. These TPA-final values are persisted to the permanent enrollment where applicable." %}

{% translate "If information is missing, Raise Query creates a dedicated GLIS query ticket related to the main transaction ticket and pauses the case in TPA Query. The requester and TPA exchange messages/attachments through DaisyUI chat displayed inside this step. Resolving the query closes the query ticket and resumes TPA processing." %}

{% translate "Users do not need to leave the TPA case to answer a query. Previous resolved conversations remain available inside the same workflow section." %}
